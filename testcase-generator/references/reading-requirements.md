# 如何阅读需求文档

目标：把需求文档转化为一份"可测的原子事实清单"，再据此设计测试点。

## 阅读三步法

### 步骤 1：通读并过滤

1. 通读全文，标记出**功能性描述**（有操作、有对象、有规则、有预期）。
2. 剔除以下冗余内容，它们不产生测试点：
   - 背景介绍、目标愿景、名词解释
   - 总结性、概述性语句
   - 与被测对象无关的说明
3. 对每一段功能描述，问三个问题：**谁**在**什么条件下**做了**什么**，系统应**如何响应**？

### 步骤 2：梳理层级

- 按需求的**实际结构**梳理：主模块 → 子模块 → 子功能 → 规则。
- 沿用需求中的模块/功能命名，不要自创一套名字。
- 输出一份层级大纲，作为测试点的骨架。

### 步骤 3：拆解模糊表述

需求中常见模糊表述必须拆解为独立、具体的场景，**禁止合并**：

| 模糊表述 | 拆解方式 |
|---------|---------|
| "以此类推""同理" | 列出每一个同类项，各自成为独立测试点 |
| "支持多种格式" | 枚举每一种格式，逐个验证 |
| "对应字段做校验" | 逐字段列出校验规则 |
| "等等""其他情况" | 追问需求方；无法确认则标注「【假设】」 |

对无法从文档确认的推测，在测试点末尾标注 `【假设】<前提>`，供评审确认。

## 图文混合文档处理

当需求包含图片（流程图、原型、状态图等）时，先识别图片类型，再提取测试方向：

| 图片类型 | 识别内容 | 测试点提取方向 |
|---------|---------|---------------|
| 流程图 | 节点、连线、判断条件、起止点 | 每个路径分支、每个判断条件、异常流程 |
| UI 截图/原型图 | 界面元素、按钮、输入框、提示、布局 | 元素交互、输入验证、显示逻辑、响应式 |
| 状态转换图 | 状态节点、转换条件、触发事件 | 每个状态转换、非法转换、状态持久化 |
| 架构图 | 模块、接口、数据流向 | 接口调用、数据一致性、模块交互 |
| 表格截图 | 表头、行列数据、合并单元格 | 数据准确性、排序、筛选、边界值 |
| ER 图 | 实体、关系、基数 | 数据完整性、关联查询、约束验证 |

**处理流程**：
1. 识别图片类型和内容
2. 提取图片中的关键信息（文字 + 视觉元素）
3. 将图片信息与文字需求关联
4. 基于完整信息设计测试点

### 借助脚本提取（可选）

若文档为 PDF/Word/图片且内容较多，可用 `scripts/analyze_document.py` 提取文字与图片（依赖 pdfplumber/python-docx/Pillow，未安装时会给出提示）：

```bash
python scripts/analyze_document.py requirement.pdf -o ./extracted -r ./analysis_report.md
```

分析报告包含：文字内容摘要、图片列表（位置/尺寸）、表格数据。对关键图片（流程图/UI/状态图）补充文字描述后，再据此设计测试点。
