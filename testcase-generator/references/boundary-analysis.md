# 边界约束与场景分析方法

好的测试用例不是"想到什么测什么"，而是对每个可测点系统性地应用以下方法，覆盖正常、**边界**、异常三类场景。

## 1. 等价类划分

把输入域划分为若干等价类，每类取一个代表值即可。

- **有效等价类**：合法、系统应接受的输入。
- **无效等价类**：非法、系统应拒绝的输入。

示例：年龄字段规则「1–120 的整数」
- 有效等价类：1–120 的整数（取 25）
- 无效等价类：≤0、>120、非整数、非数字、空

每个等价类至少一个测试点；无效等价类应**逐类单独**测试，避免一个用例掩盖多个缺陷。

## 2. 边界值分析（重点）

缺陷最常出现在边界。对每个有边界的取值，测试 **on / off / in** 三组点：

对区间 `[min, max]`，取值：
`min-1（越下界）`、`min`、`min+1`、`max-1`、`max`、`max+1（越上界）`

常见边界清单：
- **数值**：最小值、最大值、0、负数、最小值-1、最大值+1、溢出值
- **字符串/集合长度**：空（0）、1、最大长度、最大长度+1、超长
- **集合/列表**：空集、单元素、首元素、尾元素、满容量、超容量
- **日期时间**：起止时间点、跨天/跨月/跨年、闰年 2/29、时区边界
- **分页**：第 1 页、最后一页、超出末页、每页 0 条/最大条数
- **精度**：小数位截断/进位、金额分位、浮点误差

示例：年龄「1–120」→ 测 0、1、2、119、120、121。

## 3. 判定表（多条件组合）

当输出由多个条件组合决定时，用判定表穷举条件真值组合，避免遗漏。

| 条件 | 规则1 | 规则2 | 规则3 | 规则4 |
|-----|------|------|------|------|
| 已登录 | 是 | 是 | 否 | 否 |
| 是VIP | 是 | 否 | 是 | 否 |
| **动作** | 享折扣 | 原价 | 引导登录 | 引导登录 |

每一列（规则）对应一个测试点。条件多时可用因果图或正交/成对(pairwise)组合压缩数量。

## 4. 状态转换测试

针对状态机（如订单：待付款→已付款→已发货→已完成/已取消）：

- **合法转换**：每条允许的状态迁移各一个测试点。
- **非法转换**：尝试跳变或逆向迁移（如"已完成"再点"付款"），验证被正确拒绝。
- **状态持久化**：刷新/重登后状态是否保持。

## 5. 异常与健壮性场景清单

对每个功能补充异常场景：

- 非法/畸形输入、特殊字符、SQL/脚本注入样本、超长文本、Emoji
- 必填项缺失、格式错误、类型不符
- 越权访问、未登录访问、Token 过期
- 网络超时、服务不可用、依赖失败、重复提交、并发冲突
- 中途取消、断电/断网恢复、幂等性

## 6. CRUD / 表单通用检查单

对增删改查与表单，逐项套用：
- 增：必填校验、唯一性冲突、边界长度、成功后状态
- 删：不存在的记录、已被引用的记录、批量删除、删除后关联数据
- 改：并发修改、部分字段更新、改为已存在的唯一值
- 查：空结果、大数据量、模糊匹配、排序、分页、筛选组合

## 约束（发散边界）

- ✅ 只基于需求**明确提及**的内容发散边界与异常。
- ❌ 不为需求未声明的功能编造用例。
- 对合理但需求未明确的边界，标注「【假设】」交由评审确认，而非默认成立。
